# 🎯 Agent Execution Patterns Guide

*Core methodologies for structured AI agent task execution and prompt optimization*

## 🎯 Overview

This guide provides foundational patterns for executing individual AI agent tasks effectively and reliably. Focused on prompt engineering fundamentals and single-agent optimization, these patterns establish the building blocks for successful AI interactions before scaling to more complex orchestration scenarios.

## ⏱️ Time-Boxed Execution Frameworks

### Session Structure Optimization 🕐

**Single-Focus Session Design**
```
Session Characteristics:
- Autonomous execution in isolated environments
- Complete workflow: analysis → implementation → testing → iteration
- Single objective focus to prevent scope creep
- Natural completion points with deliverable outputs
- Self-contained context and requirements
```

**Time Constraint Management**
- **Fixed Duration Windows**: 15-minute focused execution periods
- **Progress Checkpoints**: Regular validation of advancement toward goals
- **Scope Boundaries**: Clear definition of what can be accomplished in timeframe
- **Completion Criteria**: Specific indicators of successful session closure

**Pre-Session Context Preparation**
```
Required Information Package:
1. Problem Statement → Clear description of objective
2. Acceptance Criteria → Specific deliverable requirements
3. Resource Hints → Relevant files, functions, and dependencies
4. Constraint Notes → Special requirements or limitations
5. Success Metrics → How completion will be measured
```

### Task Scoping Methodologies 📦

**Comprehensive Single-Prompt Strategy**
```
Prompt Structure:
- End-to-end coverage combining related sub-tasks
- Multi-step capability expectations
- Complete context provision
- Explicit constraint communication
- Clear success definition

Example Format:
"Implement feature X with functionality Y, include unit tests, 
update documentation, ensure backward compatibility, 
and verify all tests pass"
```

**Bullet-Style Requirements Format**
```markdown
## Task: [Objective Name]

**Core Requirements:**
1. Primary functionality implementation
2. Testing and validation
3. Documentation updates
4. Error handling and edge cases
5. Integration verification

**Acceptance Criteria:**
- [ ] Feature works as specified
- [ ] Test coverage >90%
- [ ] Documentation complete
- [ ] No breaking changes
- [ ] Performance within limits
```

## 🎯 Prioritization and Planning Frameworks

### Value-Based Task Assessment 📊

**Impact Assessment Matrix**
```
Evaluation Dimensions:
1. Business Impact (40%) → User value and strategic importance
2. Technical Impact (30%) → System improvement and debt reduction  
3. Implementation Feasibility (20%) → Likelihood of successful completion
4. Dependency Resolution (10%) → Unblocking of other work streams
```

**AI Capability Alignment**
```
Optimal Task Characteristics:
✅ Well-defined scope and clear success criteria
✅ Sufficient complexity to justify AI involvement
✅ Complete context available for autonomous execution
✅ Testable and verifiable outcomes
✅ Minimal external dependencies

Avoid:
❌ Ambiguous or exploratory requirements
❌ Deep domain knowledge requirements
❌ Multi-system coordination needs
❌ Highly creative or subjective tasks
```

### Dynamic Prioritization Strategies 🔄

**Real-Time Priority Adjustment**
```
Priority Factors:
- Critical bug severity and user impact
- Strategic initiative alignment
- Resource availability and constraints
- Dependency chain blocking potential
- Risk mitigation requirements

Adjustment Triggers:
- Emergency issue escalation
- Resource constraint changes
- Strategic priority shifts
- Dependency resolution
- Performance threshold breaches
```

**Coverage Balance Framework**
```
Resource Allocation Strategy:
- High-Impact Projects: 40-50% of agent capacity
- Medium-Impact Projects: 30-35% of agent capacity  
- Maintenance Tasks: 15-20% of agent capacity
- Innovation/Exploration: 5-10% of agent capacity
```

## 🚨 Error Handling and Recovery Fundamentals

### Basic Failure Detection and Response 🔍

**Simple Failure Detection**
```
Common Alert Triggers:
- Task timeout or incomplete execution
- Clear error messages or exceptions
- Output quality below standards
- Resource limitations encountered
- Requirement misunderstanding indicators
```

**Failure Classification**
```
Basic Failure Types:
1. Resource Constraints → Time, memory, or processing limits
2. Context Issues → Unclear or incomplete requirements
3. Technical Complexity → Task beyond current capability
4. Quality Issues → Output not meeting standards
5. Understanding Gaps → Misinterpretation of requirements
```

### Simple Recovery Strategies 🔄

**Basic Recovery Approach**
```
Recovery Options:
1. Retry with Clarification → Request additional context
2. Scope Reduction → Break task into smaller components
3. Alternative Approach → Try different methodology
4. Human Consultation → Escalate for guidance
5. Partial Completion → Deliver what's possible and document gaps
```

**Progress Preservation**
```
Work Conservation:
- Save partial progress to development branches
- Document completion status clearly
- Provide detailed handoff notes
- Preserve context for continuation
- Update task planning with lessons learned
```
